# 练习任务

[[首页]] · [[01-应用崩溃/00-章节导航|章节导航]] · [[01-应用崩溃/B-CR05/00-案例导航|本例导航]] · [[案例索引]] · [[工具索引]]

```sh
sadboard run crash-sigbus
sadboard verify crash-sigbus
# 使用上一步打印的实际目录：sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fault.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fault.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。截断正在映射的同一 inode 实际触发 SIGBUS=7；参考版写新 inode 后 rename，旧映射仍读到完整旧内容。mapped-source.bin 为本现场专属文件。

现场内 `crash-sigbus-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在私有实验文件上 mmap 两页，再由受控进程 ftruncate 到零，读者访问原映射页；不要操作系统映像。参考版用写新文件再原子替换，读者持有稳定版本。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** SIGBUS 一定表示硬件故障吗？为什么原子改名不能等同于截断同一个已映射文件？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。
