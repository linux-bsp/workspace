## 现象与原理

**生产现场与异常现象。** 协议递归解析或图像处理函数加入大局部数组，线程偶发退出；全局内存看起来仍充足。

**原理与容易误判的地方。** 线程栈上限与系统可用 RAM 不是同一约束。访问 guard 或无法扩展的栈映射可产生 SIGSEGV；堆仍有空闲不会自动扩大 pthread 栈。损坏返回地址又是不同问题，需要依据 SP、映射和调用深度区分。

## 练习任务

设备端：运行“递归或大栈数组耗尽工作线程栈”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run crash-stack
```

设备端：执行“递归或大栈数组耗尽工作线程栈”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify crash-stack
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fault.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fault.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。子线程栈取平台最小值与 64 KiB 的较大者（当前 AM625 为 128 KiB），递归 65 层、每层触碰 4 KiB，实际 SIGSEGV=11。参考版执行深度上限检查，拒绝超限输入并返回 2；不是无限扩大线程栈。

现场内 `crash-stack-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 只在自建线程设置有限栈和 guard，故障函数递归并实际触碰局部数组，禁止尾调用优化；参考版限制深度或使用有界堆工作区。整个实验由 timeout 限制。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 虚拟栈保留与实际 RSS 有何不同？扩大线程栈为什么可能增加地址空间和整机风险？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** 保留 /proc/PID/maps、线程栈配置、core 的 SP 和重复栈帧；GDB thread apply all bt、info registers sp，结合编译器 -fstack-usage，而不是只看 free。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

参数查阅：[[工具手册/GDB|本方向基础工具参数与边界]]。

## 内核流程与汇编

**内核阅读入口。** [mmap.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/mm/mmap.c)：expand_stack；[fault.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/arch/arm64/mm/fault.c)：do_page_fault。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 限制协议嵌套深度并避免在深调用链分配大数组；根据实际最坏路径设定栈预算，保留 guard，不能无限增大所有线程的栈。

**量化验收与现场恢复。** 边界内深度正常，超界输入被显式拒绝；测得栈高水位低于预算，堆工作区仍受总内存限制。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
