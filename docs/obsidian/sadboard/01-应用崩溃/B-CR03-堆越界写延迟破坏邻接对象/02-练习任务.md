# 练习任务

[[首页]] · [[01-应用崩溃/00-章节导航|章节导航]] · [[01-应用崩溃/B-CR03-堆越界写延迟破坏邻接对象/00-案例导航|本例导航]] · [[案例索引]] · [[工具索引]]

```sh
sadboard run crash-overflow
```

```sh
sadboard verify crash-overflow
```

把下方路径替换为上一步打印的实际目录：

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fault.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fault.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。实际分配 32 B、故障写 33 B，Valgrind 记录 Invalid write，退出码 99；参考版写 32 B，退出 0。overflow-*.valgrind 保存独立原始记录。也可用 case-suite --overflow-child bug 直接在 GDB 中观察写入指令。

现场内 `crash-overflow-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 受控程序申请 32 字节，故障版循环写 33 字节；用 Valgrind 运行，不假设每次都会产生 SIGSEGV。参考版对长度、终止符和整数乘法边界进行检查。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 为什么 ASLR、优化级别或日志语句会改变崩溃位置？如何把对象越界与缺页异常分开？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。
