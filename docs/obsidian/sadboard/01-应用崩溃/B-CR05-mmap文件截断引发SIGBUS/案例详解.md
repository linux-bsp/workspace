## 现象与原理

**生产现场与异常现象。** 日志轮转、模型文件更新或共享数据文件替换后，映射读者出现 Bus error，容易被误判为硬件总线故障。

**原理与容易误判的地方。** 虚拟地址仍处于映射范围，不代表文件对应的页还存在。文件缺页处理发现访问越过有效文件内容，可以返回 VM_FAULT_SIGBUS，随后由架构异常处理发信号。普通 rename 与对同一 inode 的 truncate 对映射的影响不同。

## 练习任务

设备端：运行“mmap文件截断引发SIGBUS”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run crash-sigbus
```

设备端：执行“mmap文件截断引发SIGBUS”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify crash-sigbus
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fault.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fault.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。截断正在映射的同一 inode 实际触发 SIGBUS=7；参考版写新 inode 后 rename，旧映射仍读到完整旧内容。mapped-source.bin 为本现场专属文件。

现场内 `crash-sigbus-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在私有实验文件上 mmap 两页，再由受控进程 ftruncate 到零，读者访问原映射页；不要操作系统映像。参考版用写新文件再原子替换，读者持有稳定版本。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** SIGBUS 一定表示硬件故障吗？为什么原子改名不能等同于截断同一个已映射文件？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** GDB 查看 $_siginfo、故障地址与 maps 的文件偏移；strace -f -e mmap,munmap,ftruncate,rename，关联 inode、文件长度和更新时间。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [filemap.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/mm/filemap.c)：filemap_fault；[fault.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/arch/arm64/mm/fault.c)：do_page_fault。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 为共享文件定义版本发布协议；新内容先写入并完成校验，再原子发布。不要靠捕获 SIGBUS 后继续使用已失效的映射来修复数据一致性。

**量化验收与现场恢复。** 反复更新时读者只能读到完整旧版或完整新版；截断故障有清晰 SIGBUS 证据，修复后无混合版本或坏校验。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
