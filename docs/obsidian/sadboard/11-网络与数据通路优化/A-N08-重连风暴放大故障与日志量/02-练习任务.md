设备端：运行“重连风暴放大故障与日志量”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run net-reconnect
```

设备端：执行“重连风暴放大故障与日志量”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify net-reconnect
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例为固定有界负载，无额外参数。源码 [suite-advanced-network.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-advanced-network.c)；私有 loopback 服务在100 ms后才listen。故障20次立即重试耗尽预算；参考带固定种子 jitter 的有上限指数退避，在同一恢复时间线成功收到42。记录每次 errno/尝试次数，全部 fd 回到基线；不向外网或管理服务器发重连风暴。

`net-reconnect-{bug,fixed}.out/.trace` 分别保存摘要与原始事件，字段 observed/auxiliary 的含义以上述本例定义为准。摘要、trace 和完成数必须相符。与正常业务输出不同的故障结果会由本例契约明确识别；不能拿最外层退出0证明没有异常。性能题同时保留 cpu_ns/wall_ns，至少三次再评价时序，不只看资源上界或一次漂亮数字。

**实际复现负载。** 私有 loopback 服务在100 ms后才listen。故障20次立即重试耗尽预算；参考带固定种子 jitter 的有上限指数退避，在同一恢复时间线成功收到42。记录每次 errno/尝试次数，全部 fd 回到基线；不向外网或管理服务器发重连风暴。
