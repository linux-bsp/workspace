# 练习任务

[[首页]] · [[11-网络与数据通路优化/00-章节导航|章节导航]] · [[11-网络与数据通路优化/A-N07/00-案例导航|本例导航]] · [[案例索引]] · [[工具索引]]

```sh
sadboard run net-priority
sadboard verify net-priority
# 完成后使用打印的实际目录执行 sadboard check
```

本例为固定有界负载，无额外参数。源码 [suite-advanced-network.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-advanced-network.c)；私有 veth 共享 1 Mbit/s 队列，先发送64个512 B bulk，再发送16个64 B控制；FIFO TBF 对比带控制高优先级的 HTB。逐项 ACK 测 RTT，全部80包及 checksum=2136必须完成；保留 qdisc/pcap，不改变管理链路。

`net-priority-{bug,fixed}.out/.trace` 分别保存摘要与原始事件，字段 observed/auxiliary 的含义以上述本例定义为准。摘要、trace 和完成数必须相符。与正常业务输出不同的故障结果会由本例契约明确识别；不能拿最外层退出0证明没有异常。性能题同时保留 cpu_ns/wall_ns，至少三次再评价时序，不只看资源上界或一次漂亮数字。

**实际复现负载。** 私有 veth 共享 1 Mbit/s 队列，先发送64个512 B bulk，再发送16个64 B控制；FIFO TBF 对比带控制高优先级的 HTB。逐项 ACK 测 RTT，全部80包及 checksum=2136必须完成；保留 qdisc/pcap，不改变管理链路。

**面试/评审追问。** 同一 TCP 流内能否只靠 DSCP 给后面的命令插队？严格优先与公平队列分别有什么风险？
