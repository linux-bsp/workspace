## 现象与原理

**生产现场与异常现象。** 抓包看到消息到达，应用序号仍跳跃，增大发送重试后反而更严重。

**原理与容易误判的地方。** 报文到达抓包点不代表成功进入 socket 或被应用取走。socket 缓冲按 skb 内存开销记账，并非单纯 payload 字节；Linux 还可能调整或翻倍请求值。

## 练习任务

设备端：运行“UDP接收队列溢出而非链路丢包”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run net-udpqueue
```

设备端：执行“UDP接收队列溢出而非链路丢包”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify net-udpqueue
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-network.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-network.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。私有 netns 的 UDP 接收缓冲设为 4096，故障先突发 128×512 B 再读，实际 RcvbufErrors 增长；参考及时接收 128 条且 checksum=8128。丢失数与命名空间统计对账。

现场内 `net-udpqueue-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在私有 netns 设置实验 socket 小 SO_RCVBUF，发送有序号的有限突发，受控暂停接收；参考版及时排空并记录无法处理的负载，不改变管理网卡。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 为什么 tcpdump 收到与应用收到不相等？放大接收缓冲为什么可能恶化陈旧数据延迟？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** 关联发送/接收序号、netns 内 UDP 统计、SO_RXQ_OVFL 辅助信息和实际 getsockopt 值；抓包本身也要检查是否丢样。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [udp.c](https://github.com/linux-bsp/linux-7.0/blob/master/net/ipv4/udp.c)：__udp_queue_rcv_skb、__udp_enqueue_schedule_skb、udp_recvmsg；[sock.c](https://github.com/linux-bsp/linux-7.0/blob/master/net/core/sock.c)：socket 接收内存记账。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 提高接收调度及时性，分离接收和重业务处理，必要时采用有界队列及明确丢弃策略；缓冲增大只是有限突发预算。

**量化验收与现场恢复。** 在同样输入负载下核对 wire、socket 和业务三层的丢失，保留队列高水位和端到端时延，不能只看收到的包数。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
