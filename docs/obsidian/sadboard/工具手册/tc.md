## 解决的问题

观察 qdisc 排队与丢包，并理解 netem 对网络故障的注入方式。

## 工作原理与准备

qdisc 管理设备出口排队；延迟在哪一侧配置、流量方向及是否双向注入决定观测结果。命名空间实验不应修改管理网口 eth0。

## 参数与结果解释

| 参数/字段 | 含义与判断方法 |
| --- | --- |
| `-s qdisc show dev IFACE` | 查看指定接口的累计发送、丢包和积压。 |
| `netem delay` | 给配置所在出口添加排队延迟。 |
| `netem loss` | 按设定条件制造丢包，保留实际参数。 |
| `root/parent/handle` | 描述 qdisc 挂载层次与标识，修改前核对原有配置。 |

## 操作步骤

设备端：只读检查自己实验命名空间中指定接口的 qdisc，先替换两个占位符。

```sh
ip netns exec LEFT tc -s qdisc show dev IFACE
```

## 判断边界

计数是累计值，应比较同一次测试前后差值。出口排队延迟不是单向传播时延，也不是应用端到端延迟；注入、测量和恢复步骤见对应案例。
