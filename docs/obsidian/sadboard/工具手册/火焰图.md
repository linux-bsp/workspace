# 火焰图

[[首页]] · [[工具索引]] · [[案例索引]]

## 解决的问题

从采样调用链定位 CPU 成本集中在哪些调用路径。

## 工作原理与准备

折叠工具将相同调用栈的权重合并，再绘制 SVG；横向宽度代表样本权重，纵向是调用层次。普通 CPU 火焰图的横轴不是时间。`--countname` 只改变显示标签，不会把样本数换算为精确的 CPU 周期总量。

## 参数与结果解释

| 参数/字段 | 含义与判断方法 |
| --- | --- |
| `perf script --no-inline -i FILE` | 把原始样本导出为调用栈文本。 |
| `stackcollapse-perf.pl` | 将 perf 文本折叠为栈和计数。 |
| `flamegraph.pl --title TEXT` | 设置图标题。 |
| `--countname cycles` | 设置权重的显示名称；必须与采样事件/含义一致。 |

## 操作步骤

设备端：把当前可写结果根目录保存在本终端，后续路径使用同一变量。

```sh
R=$(sadboard results)
```

设备端：导出本次实际采样文件，保留原始 perf.data。

```sh
perf script --no-inline -i "$R/perf.data" > "$R/stacks.txt"
```

主机端：在已部署 FlameGraph 的目录折叠采样文本，先替换实际文件路径。

```sh
FlameGraph/stackcollapse-perf.pl stacks.txt > cpu.folded
```

主机端：绘制 SVG，再打开它观察宽栈和调用关系。

```sh
FlameGraph/flamegraph.pl --countname cycles --title 'SadBoard CPU lookup' cpu.folded > cpu.svg
```

## 判断边界

名称来自符号展开；缺符号、栈回溯失败、丢样及错误事件标签会影响判断。目标只有“等待很久”时，应同时检查调度和 I/O 证据。工具获取与固定版本见 [[附录B-构建与官方实验/02-Bootlin实验获取与运行]]。
