# cgroup-v2

[[首页]] · [[工具索引]] · [[案例索引]]

## 解决的问题

区分组内存限额、回收压力、OOM 事件与 CPU 配额等资源边界。

## 工作原理与准备

父子组共同形成约束。OOM 案例将受控负载放到专用 32 MiB 叶子组，监督与保存证据的脚本留在外部。

## 参数与结果解释

| 参数/字段 | 含义与判断方法 |
| --- | --- |
| `memory.max` | 硬上限，读取实际值而不是只看预期配置。 |
| `memory.high` | 回收/节流压力边界，与 max 及 OOM 不等价。 |
| `memory.current/stat` | 当前计费量与资源类别。 |
| `memory.events` | max、oom、oom_kill 等计数，比较测试前后增量。 |
| `memory.pressure` | 该组的内存等待压力信息。 |
| `cpu.max/cpu.stat` | CPU 预算及节流证据，结合实际层级解释。 |

## 操作步骤

设备端：组还存在时读取实际限额，先替换专用实验组名中的 PID。

```sh
cat /sys/fs/cgroup/sadboard-oom-PID/memory.max
```

设备端：读取同一组的事件计数，并与运行前的快照比较。

```sh
cat /sys/fs/cgroup/sadboard-oom-PID/memory.events
```

## 判断边界

不要在不存在组 OOM 证据时只凭 137 判定 OOM。内核可能对同一退出路径产生多个计数增量；实验结束组已清理时，读取 run 目录保存的 limits/events。
