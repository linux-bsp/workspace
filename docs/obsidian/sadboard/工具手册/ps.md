# ps

[[首页]] · [[工具索引]] · [[案例索引]]

## 解决的问题

观察进程与线程状态，选择需要进一步取证的 PID/TID。

## 工作原理与准备

进程状态是瞬时快照，线程的 Linux TID 与 GDB 内部线程号不同；低 CPU 也可能意味着等待。

## 参数与结果解释

| 参数/字段 | 含义与判断方法 |
| --- | --- |
| `-L` | 按线程显示。 |
| `-p PID` | 限定自己的目标进程。 |
| `-o` | 选择 PID、TID、状态、CPU、等待点等列。 |
| `STAT/wchan` | 结合线程栈判断运行/等待，不能单凭一个状态字符推断根因。 |

## 操作步骤

设备端：先设置自己的实际 pid，检查其各线程状态。

```sh
ps -L -p "$pid" -o pid,tid,stat,pcpu,wchan,comm
```

## 判断边界

嵌入式 ps 可能来自不同实现；本配置中的能力以实际帮助和构建配置为准。进程很短时应读统一入口保存的日志，再考虑有界的慢速复现。
