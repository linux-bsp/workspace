# gdbserver

[[首页]] · [[工具索引]] · [[案例索引]]

## 解决的问题

在设备端启动可被主机 GDB 控制的目标程序。

## 工作原理与准备

设备用 `gdbserver --once :22345 PROGRAM ARGS` 启动待调程序；主机使用本构建的
`host/bin/aarch64-buildroot-linux-gnu-gdb ELF`。`--once` 在连接结束后退出，
`:22345` 是调试监听端口；它不同于 SSH，运行期间不要让其他客户端抢占连接。

## 参数与结果解释

| 参数/字段 | 含义与判断方法 |
| --- | --- |
| `--once` | 完成一次调试连接后退出，适合手动实验。 |
| `:22345` | 监听端口，主机的 target remote 必须对应。 |
| `PROGRAM ARGS` | 调试的目标路径与原始输入；示例只启动自己的实验负载。 |

## 操作步骤

设备端：一次性启动故障程序并等待连接，保留此终端查看目标输出。

```sh
gdbserver --once :22345 /usr/libexec/sadboard/crash-bug 42
```

## 判断边界

连接建立后在主机 GDB 使用 continue。工具可以保持进程停止，SSH 连通不代表业务仍在运行。程序、共享库与主机符号必须来自同一构建。

## 配合使用

主机启动、库路径和线程命令见 [[工具手册/GDB]]。监听端口与 SSH 是不同通道；实验结束检查是否仍有自己的 gdbserver/目标进程。
