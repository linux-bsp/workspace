## 解决的问题

观察可见的动态库 API 调用及返回值，与 strace 的系统调用视角互补。

## 工作原理与准备

动态库入口和实际系统调用之间还有 libc 包装、缓存、分配器及线程逻辑。内联、静态链接或未经过可跟踪入口的调用可能不可见。

## 参数与结果解释

| 参数/字段 | 含义与判断方法 |
| --- | --- |
| `-o FILE` | 单独保存调用记录。 |
| `PROGRAM ARGS` | 启动给定实验程序并保持原始输入。 |
| `LD_LIBRARY_PATH=.` | 官方实验在当前目录查找特定库；只对该次命令生效。 |

## 操作步骤

设备端：把当前可写结果根目录保存在本终端，后续路径使用同一变量。

```sh
SADBOARD_RESULTS=$(sadboard results)
```

设备端：跟踪固定输入的参考程序，结果写入实际实验目录。

```sh
ltrace -o ${SADBOARD_RESULTS}/libcalls.txt /usr/libexec/sadboard/crash-fixed 1
```

设备端：在对应 Bootlin 实验目录观察本地库版本的 API 调用。

```sh
LD_LIBRARY_PATH=. ltrace ./authent
```

## 判断边界

没有观察到函数名不直接证明函数没有运行。调用跳板、符号可见性、优化和工具支持范围都影响结果；根因需要与 [[工具手册/strace]] 和源码对照。
