设备端：运行“分开的检查与更新导致逻辑丢失”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run sync-update
```

设备端：执行“分开的检查与更新导致逻辑丢失”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify sync-update
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-sync.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-sync.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。读写各自加锁但更新事务不原子，barrier 保证丢更新而没有 C 数据竞争；64 次更新故障只得到 32，参考事务锁得到 64。

现场内 `sync-update-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 两个线程分别在锁内读计数，解锁后经 barrier 对齐，再各自锁内写 old+1；两个操作都合法但最终只加一。参考版把整个读改写事务放在同一临界区。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 无数据竞争为什么仍可能有逻辑竞争？原子变量能否自动解决多字段一致性？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。
