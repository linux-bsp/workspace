把下方路径替换为完成后打印的实际目录：

```sh
sadboard check /srv/sadboard/实际目录
```

本例为固定有界负载，无额外参数。源码 [suite-performance.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-performance.c)；CPU3 上实际使用 SCHED_FIFO 低/中/高优先级 10/30/50；主控制器在 CPU0。低线程持锁、高线程等锁、中线程消耗 60 ms CPU。observed 为高线程等待 ns；auxiliary 表示高线程拿锁时中线程是否已完成，故障为 1、PI 参考为 0。固定工作结果 84。

`perf-priority-{bug,fixed}.out/.trace` 分别保存摘要与原始事件，字段 observed/auxiliary 的含义以上述本例定义为准。摘要、trace 和完成数必须相符。与正常业务输出不同的故障结果会由本例契约明确识别；不能拿最外层退出0证明没有异常。性能题同时保留 cpu_ns/wall_ns，至少三次再评价时序，不只看资源上界或一次漂亮数字。

**实际复现负载。** CPU3 上实际使用 SCHED_FIFO 低/中/高优先级 10/30/50；主控制器在 CPU0。低线程持锁、高线程等锁、中线程消耗 60 ms CPU。observed 为高线程等待 ns；auxiliary 表示高线程拿锁时中线程是否已完成，故障为 1、PI 参考为 0。固定工作结果 84。

**面试/评审追问。** PI 为何不能解决 ABBA？如果锁拥有者在不可中断 I/O 中，继承优先级还能解决什么？
