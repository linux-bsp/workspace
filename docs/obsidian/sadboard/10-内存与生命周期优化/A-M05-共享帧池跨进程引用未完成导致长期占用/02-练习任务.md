# 练习任务

[[首页]] · [[10-内存与生命周期优化/00-章节导航|章节导航]] · [[10-内存与生命周期优化/A-M05-共享帧池跨进程引用未完成导致长期占用/00-案例导航|本例导航]] · [[案例索引]] · [[工具索引]]

```sh
sadboard run memory-session
sadboard verify memory-session
# 完成后使用打印的实际目录执行 sadboard check
```

本例为固定有界负载，无额外参数。源码 [suite-advanced-memory.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-advanced-memory.c)；通过 SCM_RIGHTS 实际传递 8 个 memfd，消费者核对内容后退出但不回应用槽确认。故障软件表仍占 8 槽，参考在证明旧进程退出后切换 generation 并清空，拒绝旧代次。OS FD 最终都回基线，用于区分协议状态泄漏和内核引用。

`memory-session-{bug,fixed}.out/.trace` 分别保存摘要与原始事件，字段 observed/auxiliary 的含义以上述本例定义为准。摘要、trace 和完成数必须相符。与正常业务输出不同的故障结果会由本例契约明确识别；不能拿最外层退出0证明没有异常。性能题同时保留 cpu_ns/wall_ns，至少三次再评价时序，不只看资源上界或一次漂亮数字。

**实际复现负载。** 通过 SCM_RIGHTS 实际传递 8 个 memfd，消费者核对内容后退出但不回应用槽确认。故障软件表仍占 8 槽，参考在证明旧进程退出后切换 generation 并清空，拒绝旧代次。OS FD 最终都回基线，用于区分协议状态泄漏和内核引用。

**面试/评审追问。** 文件描述符传递复制了什么？进程退出后为何应用槽状态仍可能泄漏？
