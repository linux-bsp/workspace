# 练习任务

[[首页]] · [[10-内存与生命周期优化/00-章节导航|章节导航]] · [[10-内存与生命周期优化/A-M03-数据流水线多次复制和缓冲池生命周期错误/00-案例导航|本例导航]] · [[案例索引]] · [[工具索引]]

```sh
sadboard run memory-frames
```

```sh
sadboard verify memory-frames
```

把下方路径替换为完成后打印的实际目录：

```sh
sadboard check /srv/sadboard/实际目录
```

本例为固定有界负载，无额外参数。源码 [suite-advanced-memory.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-advanced-memory.c)；64 个 256 KiB 帧按每批 4 帧处理，三段复制对比借用 4 个固定池槽。observed 为复制字节 33554432→0，auxiliary 为分配次数 192→4，峰值 3 MiB→1 MiB，最终 live=0；每字节校验和相同。此例是用户态帧所有权，不冒充已接相机/DMA。

`memory-frames-{bug,fixed}.out/.trace` 分别保存摘要与原始事件，字段 observed/auxiliary 的含义以上述本例定义为准。摘要、trace 和完成数必须相符。与正常业务输出不同的故障结果会由本例契约明确识别；不能拿最外层退出0证明没有异常。性能题同时保留 cpu_ns/wall_ns，至少三次再评价时序，不只看资源上界或一次漂亮数字。

**实际复现负载。** 64 个 256 KiB 帧按每批 4 帧处理，三段复制对比借用 4 个固定池槽。observed 为复制字节 33554432→0，auxiliary 为分配次数 192→4，峰值 3 MiB→1 MiB，最终 live=0；每字节校验和相同。此例是用户态帧所有权，不冒充已接相机/DMA。

**面试/评审追问。** 引用计数归零是否必然意味着设备 DMA 已结束？什么时候复制反而是更简单可靠的隔离边界？
