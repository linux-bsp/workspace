# 仓库使用说明

## 文件组织

每章一个目录，`00-章节导航.md` 汇总本章笔记；案例目录统一采用“稳定编号-具体问题”，例如 `01-应用崩溃/B-CR01-缺失记录未判空导致空指针崩溃/`。编号便于索引，后缀直接说明故障或异常现象。每例分别维护现场与原理、练习任务、工具参数、内核流程、修复与验收，基础主案例另有汇编和实机证据文件。

从 [[首页]] 进入。每篇笔记有章节/案例返回链接；案例页提供上一例、下一例与学习路径。[[案例索引]] 可横向比较根因，[[工具索引]] 可按工具复习。Obsidian 原生反向链接、关系图谱与搜索即可使用，不依赖第三方插件。

## 查找和做练习

可以直接搜索 `B-CR02`，或使用 `path:"01-应用崩溃/B-CR02-配置状态不一致触发SIGABRT"` 限定目录。YAML 中的 `case`、`chapter`、`type` 和标签便于识别内容类型；工具和机制也可全文搜索，如 `TIMER_ABSTIME`、`EMFILE`。

复制 [[模板/实验报告]] 到 `实验记录/`，以日期和案例编号命名，例如 `2026-11-10-B-CR02.md`。模板中的表格可以独立填写；不要直接修改附录中的教学模板。从自己的报告链接到案例和相关工具，保留原始日志路径、固件完整 ID 与可证伪假设。大型 core、pcap、perf.data 放在结果目录。另见 [[实验记录/使用说明]]。

## 内容维护

全部教材内容直接维护在本 Obsidian 仓库内。修改对应的章节或案例笔记即可；实验报告模板放在 `模板/实验报告.md`，需要时一并更新。

在 SadBoard 工作区根目录运行：

```sh
python3 scripts/check-obsidian.py
git diff --check
```

检查器验证双链、目标标题、59 个案例入口、工作区源码路径及是否能从首页到达每篇笔记。它不启动设备或运行案例。

新建笔记后，在章节或案例导航加入双链；标题使用清晰的中文名称。移动或重命名笔记时，使用 Obsidian 的链接更新功能，并重新运行检查。跨章节引用工具、源码和原理时，链接到现有笔记，避免复制多份内容。

## 本地设置与资料来源

保留了原来的 `欢迎.md` 和 `.obsidian/` 设置。通过 Obsidian 打开 [[首页]]，可自行固定该页；不强制修改你的窗口布局。窗口状态、缓存、回收站与实验记录默认不提交；已有 app/core-plugins 等共享设置保持原样。

源码链接使用固定 Git 提交的在线地址，避免 Obsidian 不能打开仓库外源码的问题；示例命令仍从工作区根执行。链接语法参见 [Obsidian 官方内部链接文档](https://help.obsidian.md/links)。Bootlin 的资料和 CC BY-SA 3.0 署名完整保存在 [[附录C-Bootlin课程参考/00-章节导航]]，SadBoard 扩展不代表官方课程。
