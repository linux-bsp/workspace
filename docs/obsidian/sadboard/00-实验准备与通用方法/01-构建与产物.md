## 0.1 构建与产物

新克隆工作区：

主机端：初始化并更新工作区的全部源码子模块，确认下载完成后再配置 Buildroot。

```sh
git submodule update --init --recursive
```

主机端：进入 Buildroot 源码目录；下方不带 -C 的 make 命令在此终端执行。

```sh
cd buildroot
```

主机端：加载两个 external 并生成 SadBoard 标准配置；成功后再启动完整编译。

```sh
BR2_EXTERNAL="../bsp-base-external ../sadboard-external" \
  make sadboard_am625_debug_defconfig
```

配置成功后继续编译。

主机端：编译已选配置的完整系统，确认 make 成功退出后再使用镜像。

```sh
make all
```

默认产物在 `buildroot/output/images/`。需要独立输出目录时，在 workspace 根目录执行：

主机端：在独立输出目录加载 SadBoard 配置，避免混用已有工具链和构建缓存。

```sh
make -C buildroot O="$PWD/output/am625-debug-systemd" \
  BR2_EXTERNAL="$PWD/bsp-base-external $PWD/sadboard-external" \
  sadboard_am625_debug_defconfig
```

主机端：打开此输出目录的配置菜单，设置实际 SDK 与下载缓存路径并保存。

```sh
make -C output/am625-debug-systemd menuconfig
```

主机端：编译该输出目录的系统；成功退出后检查 images 下的产物。

```sh
make -C output/am625-debug-systemd all
```

若使用已有 SDK，在新的输出目录的 Toolchain 菜单选择 External toolchain、Custom、
Pre-installed，填写实际 SDK 路径和 `aarch64-buildroot-linux-gnu` 前缀，声明 GCC 15、
glibc、Linux 7.0 headers 与 C++ 支持。本机 SDK 位于
`../toolchain/aarch64-buildroot-linux-gnu_sdk-buildroot`。下载缓存通过 Build options
中的 Download dir 设置为实际的 `../dl` 目录。保存菜单配置后再编译。
默认 defconfig 使用独立构建工具链，不依赖本机 SDK。

输出已有配置时继续执行 `make all`。修改实验包源码后，需要显式重建本地包：

主机端：删除实验包的旧构建目录，确保下一步用目标编译器重新构建。

```sh
make -C output/am625-debug-systemd sadboard-labs-dirclean
```

主机端：重新生成实验程序和完整镜像，确认编译及 post-image 都成功。

```sh
make -C output/am625-debug-systemd all
```

不能把内部/外部工具链混入同一个输出目录。

| 产物 | 用途 |
| --- | --- |
| `images/release/{release,kernel,rootfs}.itb` | OTA 升级包，只更新 kernel/rootfs |
| `images/debug/vmlinux`、`System.map`、`kernel.config` | 与设备内核匹配的分析资料 |
| `images/debug/labs/`、`images/debug/source/` | 实验程序及源码 |
| `images/debug/build-info.json` | 固件 ID 与调试资料 SHA256 |
| `staging/` | 远程 GDB 的匹配 sysroot |
| `images/rootfs.tar` | fakeroot 生成的 NFS rootfs 归档，解压时保留数字 UID/GID |
| `images/netboot/{Image,k3-am625-alientek.dtb}` | TFTP 用的未压缩 ARM64 内核和独立 DTB |
| `images/netboot/manifest.json` | TFTP/NFS 产物的完整 SHA256 与参考构建 ID |

保留现有 SD 分区。默认调试启动使用下节的 TFTP/NFS 部署；本地 A/B 模式仍可通过
Device Manager 发布三个 ITB 的 tar.gz，待设备上报 success 后再触发实验。
`sdcard.img` 是工厂镜像，不用于覆盖当前实验板。

构建后先核对符号归属、SHA256、ELF 调试段和关键内核能力：

主机端：核对固件 ID、符号 SHA256、ELF 架构及调试能力；全部通过后再部署。

```sh
sadboard-external/scripts/verify-debug.sh output/am625-debug-systemd/images
```

构建入口、包构建和固件打包不使用自写 Python。设备与 Device Manager 采用原生 C 程序；上游 U-Boot/binman、OP-TEE 和主机 GDB 的 Python 由 Buildroot 的主机依赖管理。Python 仅用于本项目的主机回归测试、文档检查和串口验收工具。
