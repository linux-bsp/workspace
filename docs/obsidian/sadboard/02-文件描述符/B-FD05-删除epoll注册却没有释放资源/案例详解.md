## 现象与原理

**生产现场与异常现象。** 设备重连流程认为 EPOLL_CTL_DEL 就完成清理，实际 fd 数每次重连增加。

**原理与容易误判的地方。** 事件兴趣集合管理和文件对象生命周期是两套接口。DEL 停止关注事件，不承担替调用者关闭 fd 的职责；反过来关闭一个 fd 也不能替代正确处理它的重复引用与用户对象。

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fd.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fd.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。16 次 ADD→DEL 后，故障版仍持有 16 个 fd。trace 的 open_descriptors 是实际 /proc/self/fd 计数，DEL 不会代替 close。

现场内 `fd-epoll-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 给 32 个 socketpair 端点注册事件，故障版只 DEL 不 close；参考版同时处理 epoll interest、fd 和用户连接对象。用固定循环观察 fd 趋势。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 如果旧回调携带的 fd 已被复用，如何避免销毁新连接？为什么需要 generation 或对象身份？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** 同时记录 epoll_ctl 与 close 的次数、/proc/PID/fd 总量和应用对象计数。只看到不再收到事件不足以证明资源已释放。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [eventpoll.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/eventpoll.c)：do_epoll_ctl、ep_remove；[open.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/open.c)：close 的系统调用路径。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 集中维护一次性销毁函数并记录对象状态；用 fd 所有权和引用关系审查所有重连、失败和超时路径。

**量化验收与现场恢复。** 多轮重连后事件注册数、fd 数、业务对象数均稳定；重复清理不会误关已经复用给其他连接的 fd。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
