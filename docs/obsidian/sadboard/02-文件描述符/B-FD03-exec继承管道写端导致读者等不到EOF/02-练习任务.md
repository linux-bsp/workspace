设备端：运行“exec继承管道写端导致读者等不到EOF”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run fd-cloexec
```

设备端：执行“exec继承管道写端导致读者等不到EOF”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify fd-cloexec
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fd.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fd.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。辅助进程通过握手证明已 exec，并保持到父进程明确释放，排除启动慢的误判。故障管道 100 ms 内等不到 EOF，参考管道可读到 EOF；辅助进程退出不靠外部 kill。

现场内 `fd-cloexec-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 私有父进程创建 pipe，再启动一个两秒后退出的 exec 子进程；故障版忘记 CLOEXEC，读者等待 EOF。参考版用 pipe2(O_CLOEXEC)，全部进程限定三秒以内。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 为什么 fork 后设置父进程 FD_CLOEXEC 不会修改已继承的子进程副本？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。
