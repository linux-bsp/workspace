## 现象与原理

**生产现场与异常现象。** 日志切换或设备句柄复制路径只关闭原 fd，长期运行后 open 返回 EMFILE。

**原理与容易误判的地方。** fd 是进程表中的索引，dup 创建另一个引用同一 open file description 的索引。关闭其中一个引用不会释放另一个；共享文件偏移也能作为两者关系的证据。

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fd.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fd.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。16 次 open→dup→close 原句柄后，故障版还持有 16 个副本，参考版为 0。观测后两版都释放实验资源，before/after FD 数必须相同。

现场内 `fd-dup-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 实验子进程把 NOFILE 限制为 64，每轮 open、dup、close 原 fd，却保留副本；参考版按所有权关闭副本。记录每次编号和完整 fd 列表。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** dup 后两个 fd 是否共享偏移？为什么 /proc/sys/fs/file-nr 不一定按 fd 数等比例增长？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** strace -f -e openat,dup,dup2,dup3,close；检查 /proc/PID/fd 与 limits，区别“系统文件对象数”与“当前进程描述符数”。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [file.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/file.c)：dup、dup2、dup3 的实现；[file_table.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/file_table.c)：文件对象引用释放。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 规定借用、复制、转移所有权的接口，确保复制后的每条错误路径都释放自己的引用；不要只提高 NOFILE。

**量化验收与现场恢复。** 相同轮数下 fd 回到初始基线，正常文件偏移语义保留；低上限下不会减少业务完成数。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
