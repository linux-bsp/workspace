## 现象与原理

**生产现场与异常现象。** 设备网络看起来已断开，但服务连接数持续增加，运行一段时间后接受新连接失败。

**原理与容易误判的地方。** TCP 收到 FIN 后，应用读完已有数据会看到 EOF。CLOSE_WAIT 等待本端应用关闭，不是调小 TIME_WAIT 参数就能解决；残留对象、定时器和 epoll 引用可能共同延长生命周期。

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-fd.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-fd.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。独立 netns 中建立 16 个真实 TCP 连接，收到 FIN/EOF 后核对 TCP_INFO 的 CLOSE_WAIT=8；故障版保留 16 个 fd，参考版立即关闭。最后统一清理。

现场内 `fd-closewait-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在独立 netns 的 loopback 上反复建立连接并由对端正常关闭，故障服务读到零后仍保留 fd；参考版释放连接对象。最大连接数固定为 32。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

## 定位方法

**定位分析流程。** 在实验 netns 内用 ss -tanp，结合 /proc/PID/fd 和连接对象计数；strace -e recvfrom,shutdown,close 检查 EOF 分支，避免把正常 TIME_WAIT 与泄漏混为一谈。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [tcp_input.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/net/ipv4/tcp_input.c)：tcp_fin；[tcp.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/net/ipv4/tcp.c)：tcp_recvmsg、tcp_close。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** EOF、复位、超时和取消统一进入可重复调用的连接销毁流程；删除事件注册、停止计时器，再关闭 fd 并释放对象。

**量化验收与现场恢复。** 每批连接结束后 CLOSE_WAIT 和应用对象回到基线；所有预期报文仍正确处理，管理 eth0 不参与故障注入。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
