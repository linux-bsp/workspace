## 现象与原理

**生产现场与异常现象。** 服务无待发送数据，却持续被事件循环唤醒，采样看起来主要在 epoll_wait。

**原理与容易误判的地方。** 通常空闲 TCP socket 大部分时间可写。level-triggered 可写就绪会反复返回；事件调用本身没有 bug，兴趣集合的状态机错误才导致无业务的高频唤醒。

## 练习任务

设备端：运行“错误订阅EPOLLOUT导致空转”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run cpu-epollout
```

设备端：执行“错误订阅EPOLLOUT导致空转”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify cpu-epollout
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

sadboard check /srv/sadboard/实际目录

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-cpu.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-cpu.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。故障版对没有发送任务的管道持续关注 EPOLLOUT，参考版只等待命令 eventfd；两版最终处理同一值 42，observed 是无用就绪通知次数。

现场内 `cpu-epollout-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在私有 socketpair 或独立 netns 连接上始终订阅 level-triggered EPOLLOUT；发送队列为空时也继续关注。参考版只在确有积压且发送遇到 EAGAIN 时关注可写。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

## 定位方法

**定位分析流程。** strace -tt -e epoll_wait,epoll_ctl,sendto，统计每秒返回次数与实际发送字节；GDB 看业务发送队列是否为空。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

参数查阅：[[工具手册/perf|本方向基础工具参数与边界]]。

## 内核流程与汇编

**内核阅读入口。** [eventpoll.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/eventpoll.c)：ep_poll_callback、ep_poll；[tcp.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/net/ipv4/tcp.c)：tcp_poll。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 把事件订阅与输出缓冲区状态绑定；处理部分写入、EINTR 和 EAGAIN，连接销毁时撤销所有权。

**量化验收与现场恢复。** 无输出时停止空转，有新输出时仍及时发送；缓冲区正确排空，无重复或遗漏。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
