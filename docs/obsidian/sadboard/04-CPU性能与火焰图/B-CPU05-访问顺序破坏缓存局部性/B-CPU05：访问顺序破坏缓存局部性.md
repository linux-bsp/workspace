## 现象与原理

**生产现场与异常现象。** 同样的标定表或图像统计计算换一块 ARM 板后变慢，指令数量变化不大。

**原理与容易误判的地方。** 连续数据通常更容易利用 cache line 和预取，跨步访问增加工作集压力。但性能还依赖缓存大小、并行度、TLB 和编译器，不能从单台机器固定倍数外推到所有 SoC。

## 练习任务

设备端：运行“访问顺序破坏缓存局部性”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run cpu-locality
```

设备端：执行“访问顺序破坏缓存局部性”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify cpu-locality
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-cpu.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-cpu.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。相同 1024×1024 矩阵、4 轮访问，列优先与行优先完成 4194304 次，checksum 相同。observed 记录初始实际地址步长 4096/4 B，性能差异另用 perf 测量。

现场内 `cpu-locality-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在最多 4 MiB 的私有矩阵上比较行优先与跨行访问，固定元素数、轮数和 checksum；使用优化构建并保留可观察输出，避免循环被优化掉。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 为什么 cache-misses 不能直接解释所有变慢？如何排除编译器删掉工作量的影响？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** 先看 perf list，再测 cycles、instructions、可用 cache/TLB 事件；保留运行 CPU、频率、矩阵大小和至少三次结果。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [arm_pmuv3.c](https://github.com/linux-bsp/linux-7.0/blob/master/drivers/perf/arm_pmuv3.c)：armv8 PMU 事件支持；[arm_pmu.c](https://github.com/linux-bsp/linux-7.0/blob/master/drivers/perf/arm_pmu.c)：ARM PMU 公共路径。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 改变布局或遍历顺序，必要时分块处理；说明是否增加复制、额外内存或算法复杂度。

**量化验收与现场恢复。** checksum 和工作量一致，在匹配条件下比较 CPU 时间与可用硬件计数；不支持的 PMU 事件标为缺失。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
