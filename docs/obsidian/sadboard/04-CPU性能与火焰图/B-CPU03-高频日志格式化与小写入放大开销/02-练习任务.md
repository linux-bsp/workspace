# 练习任务

[[首页]] · [[04-CPU性能与火焰图/00-章节导航|章节导航]] · [[04-CPU性能与火焰图/B-CPU03-高频日志格式化与小写入放大开销/00-案例导航|本例导航]] · [[案例索引]] · [[工具索引]]

```sh
sadboard run cpu-logging
```

```sh
sadboard verify cpu-logging
```

把下方路径替换为上一步打印的实际目录：

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-cpu.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-cpu.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。同样 2048 行，读回逐条检查 index/value；故障逐行写 2048 次，参考每批 32 行写 64 次。使用 memfd 排除 SD/NFS 持久化干扰；持久化取舍留给进阶场景。

现场内 `cpu-logging-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在私有文件写同样 10,000 条固定记录，比较逐条格式化/写入与有限批次输出；测试文件不超过 4 MiB，先用独立 tmpfs 对照，再单独观察 NFS 的 I/O 影响。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 为什么把每行 fsync 去掉不是无条件正确的优化？异步日志队列满时如何处理？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。
