## 现象与原理

**生产现场与异常现象。** 打开调试日志后，网关吞吐下降，故障又因为关日志而消失。

**原理与容易误判的地方。** 日志成本可能来自字符串格式化、锁、系统调用、终端同步和存储等待。CPU 时间与墙钟的相对变化决定应先分析计算还是阻塞；NFS 慢不能直接归因 printf 算法。

## 练习任务

设备端：运行“高频日志格式化与小写入放大开销”故障现场，记录输出中的实际结果目录与异常证据。

```sh
sadboard run cpu-logging
```

设备端：执行“高频日志格式化与小写入放大开销”的参考修复验收，核对终端结论及保存的结果契约。

```sh
sadboard verify cpu-logging
```

设备端：把路径占位符替换为本次实际现场目录，复核该次运行的证据完整性与验收约束。

```sh
sadboard check /srv/sadboard/实际目录
```

本例固定小负载，无额外参数；全部源文件安装在 `/usr/src/sadboard/src/`。实现入口为 [suite-cpu.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite-cpu.c)，公共调度器为 [suite.c](https://github.com/linux-bsp/sadboard-external/blob/93c81e82acfdf5d54155d1b9bb750e78645d384f/package/sadboard-labs/src/suite.c)。同样 2048 行，读回逐条检查 index/value；故障逐行写 2048 次，参考每批 32 行写 64 次。使用 memfd 排除 SD/NFS 持久化干扰；持久化取舍留给进阶场景。

现场内 `cpu-logging-{bug,fixed}.out` 保存结构化度量，`.trace` 保存实际事件/资源计数，stderr/core/Valgrind 文件按案例保留。check 同时核对 trace 与摘要以及本例信号/业务契约，不会仅检查一个 passed 字符串。故障被限制在子进程或私有 namespace；run 返回的是取证控制器退出状态，真实异常信号要查看 observed/auxiliary 和 stderr，不能只看最外层 shell 的 `$?`。

**复现条件与故障注入。** 在私有文件写同样 10,000 条固定记录，比较逐条格式化/写入与有限批次输出；测试文件不超过 4 MiB，先用独立 tmpfs 对照，再单独观察 NFS 的 I/O 影响。 操作前记录版本/构建 ID、boot ID、输入、资源上限和超时。取证对象必须是自己的实验进程，设计卡中的 PID 均指该子进程。

**面试/评审追问。** 为什么把每行 fsync 去掉不是无条件正确的优化？异步日志队列满时如何处理？ 请提交：候选假设、可证伪实验、原始数据、关键源码分支、修复前后对照和未覆盖边界。只给一个参数调整或一个“修好了”的截图不算完成。

## 定位方法

**定位分析流程。** 用 strace -c -e write,writev,fsync 和 perf stat/report；统计实际行数、字节数和文件 SHA256，区分 stdout 串口与普通文件。 对照上方工具手册逐项说明命令回答了什么问题；信号/退出码、资源计数、业务完成数和时间轴必须能互相验证。优化前后采用同输入，至少保留一次负例，排除“异常只是没有触发”。

## 内核流程与汇编

**内核阅读入口。** [read_write.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/read_write.c)：vfs_write；[pipe.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/fs/pipe.c)：pipe_write；[page-writeback.c](https://github.com/linux-bsp/linux-7.0/blob/1c04c52c72b0e67ad4b5deca464ea70bc6ebb718/mm/page-writeback.c)：脏页节流路径。先确认用户态接口或信号，再向对应内核分支追踪；这些是本仓库 Linux 7.0 的源码入口，不是已经采集到的动态调用栈。

## 修复与验收

**修复方案与代价。** 结构化记录、速率限制和有界异步队列；批次同时受大小与最长等待时间约束，关键故障日志有独立持久化策略。

**量化验收与现场恢复。** 记录内容和条数相同，系统调用数下降；增加的刷出延迟和异常断电可能丢失的窗口必须量化。 最后停止实验进程，释放私有文件、描述符或 namespace；保存证据再清理，不删除系统日志，不影响管理网络。
