# SadBoard Obsidian 手册

在 Obsidian 中选择“打开文件夹为仓库”，打开本目录下的 **`sadboard/`**，从[首页](sadboard/首页.md)进入。

## 内容组织

- [案例索引](sadboard/案例索引.md)：35 个基础案例、24 个进阶案例；每例一篇完整详解。
- [工具索引](sadboard/工具索引.md)：每个工具一篇手册，集中维护原理、参数、操作和判断边界。
- [实验报告模板](sadboard/附录A-实验报告/01-实验报告模板.md)：复制后填写自己的假设、证据与验收结果。

案例中的“使用工具”链接到对应手册；工具手册的“使用场景”反向链接到具体案例的定位章节。
案例保留场景特定的输入、命令、内核路径、汇编和证据解释，通用参数说明只维护在工具手册中。

目录示意：根目录只保留三个阅读入口；案例正文、工具手册和附录各归其位。

```text
sadboard/
├── 首页.md、案例索引.md、工具索引.md
├── 00-实验准备与通用方法/       # 五篇连贯的准备与基础正文
├── 01-应用崩溃/ ... 11-网络与数据通路优化/
│   └── B-CR01-缺失记录未判空导致空指针崩溃/
│       └── 案例详解.md          # 现象、练习、原理、定位、验收
├── 工具手册/
│   ├── GDB.md、strace.md、perf.md
│   └── ...                   # 每个工具独立维护，带案例反向链接
└── 附录A-实验报告/ ... 附录D-iMX6ULL历史排错/
```

笔记使用普通 Markdown 标题，不设置 YAML 属性。案例编号体现在目录名和标题中；通过 Obsidian 的搜索、反向链接和关系图即可查阅，不要求额外插件。

## 命令与维护约定

可批量执行的 setenv、GDB 设置或静态变量配置放在同一块；构建、连接、故障触发和验收等需要判断结果的步骤分开。
每个代码块前写清执行位置、用途或检查要点；多行续写、管道及子 shell 保持完整。
后台启动与 PID 保存、退出码保存与打印放在一起。源代码、配置和日志输出保持完整示例。

维护时修改内容所属的案例或工具手册。移动笔记后同步更新链接，不保留重复导航页或旧路径占位文件。
工作区源码使用固定提交的在线链接；静态推导、示意输出和真实实机证据分别标注。
Bootlin 来源和许可见[资料使用与来源](sadboard/附录C-Bootlin课程参考/04-资料使用与来源.md)。

主机端：从 SadBoard 工作区根目录检查双链、标题、59 例覆盖、源码路径和案例/工具双向链接。

```sh
python3 scripts/check-obsidian.py
```

主机端：检查本次修改的补丁格式与空白，再提交文档。

```sh
git diff --check
```

## 个人记录与实机证据

需要做记录时，在仓库内自行创建 `实验记录/`，将模板复制为 `日期-案例编号.md`。
该目录默认忽略；个人窗口状态、缓存、回收站和插件也不提交。保留现有 `.obsidian/` 设置。
大型 core、pcap、perf.data 继续保存在实际实验结果目录，报告中记录路径、固件完整 ID 和附件哈希。

实机验收统一记录在[AM625 实机验收档案](../am625-debug-validation.md)，不在知识库重复维护。
