# SadBoard 故障定位教材与学习路线

本教材面向希望从嵌入式 Linux 底层机制学习定位方法的读者。章节使用当前 AM6254
实机与仓库固定内核，按照“先认识现象，再建立模型，最后用源码解释证据”的顺序展开。
命令后应先写预测，再执行和解释输出；不要把 `verify` 当作学习过程本身。

## 第一篇：环境与共同基础

1. [快速上手](am625-quickstart.md)：构建、SSH、符号、首个在线/离线 GDB 实验。
2. [故障定位基础](debugging-foundations.md)：退出、内存、时间、并发、网络、跨启动证据。
3. [场景管理](scenario-lifecycle.md)：输入契约、监督、记录、验收与取消的区别。
4. [工具手册](debug-tools.md)：参数、工具可见范围、符号与测量限制。

基础要求：能读简单 C 指针、循环和函数；知道 shell 重定向和进程基本概念。
暂时不熟悉页表、futex 或 PMU 不影响开始，各案例会从现象逐步解释。

## 第二篇：从简单失败到资源与性能问题

| 顺序 | 章节 | 学完应能解释 |
| --- | --- | --- |
| 1 | [应用崩溃与 core](cases/crash.md) | 输入如何变成错误指针、信号和具体访存指令 |
| 2 | [描述符泄漏与耗尽](cases/fd-exhaustion.md) | FD、打开对象、进程限制、open/close 与资源所有权 |
| 3 | [内存泄漏与 OOM](cases/oom.md) | 分配、写触、计费、回收、杀进程和泄漏来源的关系 |
| 4 | [CPU 热点](cases/cpu.md) | 算法工作量如何体现为时间、事件和采样权重 |
| 5 | [锁等待](cases/lock.md) | 业务锁、futex 与调度之间的分层和时间线 |
| 6 | [网络异常](cases/network.md) | 链路、协议、队列、传输和应用证据的边界 |
| 7 | [panic 与启动恢复](cases/kernel-panic.md) | 原始栈、重启原因、失败与恢复日志如何关联 |

panic 放在最后，严格使用该章启动窗口流程，不加入批量自动测试。
描述符案例适合在 OOM 前学习：先理解资源所有权与局部预算，再进入物理页与组计费。

## 第三篇：源码精读与独立练习

先完成 [分级练习册](workbook.md) 的 L1，能解释每条证据后再挑战 L2/L3。
[内核阅读笔记](kernel-reading-notes.md) 帮助区分正常慢路径、错误分支和共同终止路径。
每次使用 [实验报告模板](lab-report-template.md) 保存假设、反例及修复对照。

章节中源码箭头表示经过省略的逻辑路径，不冒充实机完整调用栈。不同内核和 libc
实现会变化，精确行号应以本固件配套源码为准；实际执行范围见
[验证记录](am625-debug-validation.md)。扩展练习未列入记录时，不表示已经实测。

## 如何判断真正学会

能复现属于起点；能够在不看答案时选工具、预测结果、排除相近问题、解释关键源码分支，
并证明修复保持了同样业务，才算完成一章。性能结论必须有重复测量，恢复结论必须有
跨启动证据。遇到证据不足应明确写下缺口，再设计下一次实验。
