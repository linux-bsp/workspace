# HWID 编码规范

本规范用于内部设备的产品归属、硬件识别和固件兼容性匹配。HWID 标识一类确定的设备配置；同配置的多台设备共享 HWID，各台实物设备另用序列号区分。

## 编码格式

```text
S-PP-JJJJ-MMMM-HH-RRR
```

所有字段使用十六进制编码。分隔符仅用于显示，实际保存为固定 16 个十六进制字符，共 64 位、8 字节。文本统一使用小写，保留前导零；JSON 使用字符串，避免整数精度问题。

| 字段 | 字符数 | 位数 | 含义 | 示例 |
| --- | ---: | ---: | --- | --- |
| `S` | 1 | 4 | HWID 编码格式版本 | `1`：第一版编码规则 |
| `PP` | 2 | 8 | 产品线 | `01`：计算载荷产品线 |
| `JJJJ` | 4 | 16 | 项目 ID | `0001`：H200；`0002`：飞腾 S5000C |
| `MMMM` | 4 | 16 | 产品型号 | `0001`：CCM 桥接板；`0002`：星务计算机 |
| `HH` | 2 | 8 | PCB 硬件版本，主版本、修订版本各占 4 位 | PCB 丝印 V1.2 对应 `12` |
| `RRR` | 3 | 12 | 保留字段 | 当前固定为 `000` |
| 合计 | 16 | 64 | 8 字节 | `S-PP-JJJJ-MMMM-HH-RRR` |

## 位分配与版本解释

| 字段 | 位范围（最高位为 63） |
| --- | --- |
| `S` | 63–60 |
| `PP` | 59–52 |
| `JJJJ` | 51–36 |
| `MMMM` | 35–20 |
| PCB 主版本 | 19–16 |
| PCB 修订版本 | 15–12 |
| `RRR` | 11–0 |

PCB 版本严格对应实物丝印。主版本和修订版本各取值 0～15；例如 `10` 对应 V1.0，`12` 对应 V1.2，`1a` 对应 V1.10。HWID 格式版本与 PCB 版本、软件版本分别管理。

## 当前 AM625 验证板

用户指定的 HWID：

```text
显示：1-01-0001-0001-10-000
存储：1010001000110000
字节：10 10 00 10 00 11 00 00
```

| 属性 | 值 |
| --- | --- |
| HWID 格式版本 | 1 |
| 产品线 | 01：计算载荷产品线 |
| 项目 ID | 0001：H200 |
| 产品型号 | 0001：CCM 桥接板 |
| PCB 版本 | V1.0 |
| 保留字段 | 000 |

## 使用规则

- 项目、产品及版本编号统一登记，发布后不复用或改变原有含义。
- 按本项目约定，项目 ID、产品型号及 PCB 版本对应确定的硬件和部署配置；HH 始终记录真实 PCB 版本，软件更新不得修改它。
- 固件支持的 HWID 以完整值明确声明，不通过截断、通配符或版本大小推断兼容性。
- 第一版仅接受格式版本 `1`、保留字段 `000`；缺失、损坏或不支持的身份不能从待安装固件中自动补写。
- 设备身份保存为 U-Boot 环境变量 `hwid`，复用现有冗余环境。普通 OTA、A/B 切换和回退不得修改该变量；维护时可显式修改，用于不同身份的验证。恢复默认环境或重刷环境后，需要重新配置正确 HWID。
- 存储后端可以是 SD、eMMC 或 SPI NOR；HWID 字符串格式保持一致，存储位置及冗余由对应 U-Boot 环境后端管理。NAND 暂不纳入实现范围。
- 固件内容继续通过软件版本与完整 SHA256 标识，与 HWID 分别管理。

各存储后端、使用方法与启动阶段验证结果见 [AM625 HWID 环境存储与验证](validation-history.md#hwid-environment-validation)。
